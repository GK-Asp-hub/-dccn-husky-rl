# Эксперимент A — детерминированное препятствие на пути

Пять эпизодов одной и той же постановки с разными контурами управления. Цель — показать **где реактивная политика TD3 фундаментально не справляется** и какое минимальное расширение архитектуры закрывает задачу.

## Постановка

- Робот стартует в `(0, 0)`.
- Цель в `(4, 0)` — прямо вперёд, расстояние 4 м.
- Одно цилиндрическое препятствие в `(2, 0)`, радиус 0.5 м — **точно на прямой между стартом и целью**.
- Среда полностью детерминирована: сиды влияют только на инициализацию RNG, layout и физика идентичны во всех прогонах.

Реализация: `envs/husky_obstacle_deterministic_env.py` (наследник `HuskyObstacleEnv` с переопределёнными `_sample_goal` и `_spawn_obstacles`). Eval-pipeline: `experiments/exp_a_final.py`. Запись видео: `experiments/exp_a_video_mp4.py`.

## Что в роликах

Все ролики записаны на одном и том же сиде (`seed=1000`), на одной и той же обученной модели `husky_obstacle_td3_v3_steppen036` — различается **только контур управления**.

| Файл | Длит. | Контур управления | Итог |
|------|-------|-------------------|------|
| `01_TD3_only.mp4` | ~3 с | Чистый TD3 (reactive policy alone) | ❌ collision на 19 шаге |
| `02_TD3_LQR.mp4` | ~3 с | TD3 + LQR-residual α=0.2 (как в статье) | ❌ collision на 19 шаге |
| `03_TD3_LidarAvoid.mp4` | ~5 с | TD3 + лидарный avoidance с гистерезисом | ❌ collision на 45 шаге |
| `04_TD3_MapAvoid.mp4` | ~25 с | TD3 + map-aware avoidance (знание позиций препятствий) | ✅ goal_reached на 228 шаге |
| `05_TD3_MapAvoid_LQR.mp4` | ~25 с | TD3 + LQR + MapAvoid (комбо) | ✅ goal_reached на 228 шаге |

## Главные наблюдения

**TD3 alone и TD3+LQR врезаются за 1 секунду.** Эта конфигурация — out-of-distribution для модели: тренировочные эпизоды содержали 3-5 случайных препятствий вокруг арены, не сценарий «препятствие точно на курсе с самого старта». LQR здесь не помогает — он работает по углу к цели, а цель находится прямо за препятствием, и он подталкивает робот в ту же точку, куда уже едет TD3.

**TD3+LidarAvoid не закрывает задачу.** Контроллер избегания на основе 16-лучевого лидара (угловое разрешение 22.5°) подвержен фундаментальной проблеме дискретизации: при близких препятствиях диаметра ~1 м между соседними лучами появляется слепая зона, в которой объект перестаёт детектироваться. Робот огибает препятствие первый раз, потом TD3 поворачивает к цели, лидар-боковой луч промахивается мимо препятствия, и робот идёт на повторный контакт.

**TD3+MapAvoid решает задачу на 100%.** Тот же алгоритм избегания, но использующий точные координаты препятствий вместо лидар-лучей. Во время активного режима AVOIDANCE робот описывает дугу вокруг препятствия (видно на 04 и 05). Затем гистерезис отпускает контроль обратно TD3+LQR, который доводит робот до цели.

**MapAvoid + LQR ≈ MapAvoid.** LQR-вклад нулевой во время avoidance (avoidance берёт управление полностью), а в TD3-режиме после avoidance путь до цели короткий и LQR-сглаживание не успевает накопить заметный эффект.

## Что это означает архитектурно

Соответствует формулировке из исходной встречи с научником о «нескольких сценариях с тумблер-переключением по дельте ошибки»:

- **Сценарий 1 — NAVIGATION:** TD3 + LQR-residual (плавное следование к цели по обученной policy с классической стабилизацией курса).
- **Сценарий 2 — AVOIDANCE:** map-aware avoider (хирургический объезд по известной геометрии).
- **Тумблер:** distance to nearest obstacle edge < 1.5 м → AVOIDANCE; > 2.5 м → NAVIGATION (гистерезис против дребезга на границе).

MapAvoid в текущей реализации — это **upper bound** для архитектуры с modeled-knowledge. На реальном роботе он питается либо предоставленной картой, либо SLAM-картой, накапливаемой по тем же лидар-данным во времени (а не мгновенным single-frame срезом 16 лучей).

## Технические детали

- Кодек: H.264, контейнер mp4
- Запись через PyBullet `STATE_LOGGING_VIDEO_MP4` + ffmpeg, как в основных видео paper-v1
- Камера: follow (повторяет за роботом сверху-сзади)
- Realtime factor: 1.5 (медленнее реального времени для лучшей видимости манёвров)

Эпизоды записаны на `husky_obstacle_td3_v3_steppen036_best/best_model.zip` (та же модель, что в видео `02_stage2a_v3_baseline.mp4` и `03_stage2a_v3_planner.mp4` из основной серии).

## Воспроизведение

```bash
python experiments/exp_a_video_mp4.py
```

Опции:
- `--obstacle-y-offset 0.4` — препятствие смещено вбок (исследование границ MapAvoid).
- `--obstacle-radius 0.7` — большее препятствие.
- `--top-down` — вид сверху вместо follow-камеры.
- `--only 04_TD3_MapAvoid` — записать только одну конфигурацию.

Headless ablation без видео:

```bash
python experiments/exp_a_final.py --seeds 3
```
